AWS · TERRAFORM · EVENT-DRIVEN ARCHITECTURE

Serverless
Document Pipeline.

A practical cloud architecture that detects uploaded documents, validates basic file metadata, and sends email notifications—with buffering, retries, and dead-letter handling built in.

S3SQS + DLQLambdaSNSCloudWatchIAMTerraform
01 / THE USE CASE

The problem & solution

!

Before: manual document checks

A business receives invoices and application forms. Team members check for uploads, inspect them manually, and message colleagues. New files may be missed; failed tasks are difficult to recover.

✓

After: event-driven processing

Uploading a file automatically queues a task. Lambda checks file metadata and publishes an outcome to SNS. Failed executions are retried and finally routed to a dead-letter queue.

02 / SYSTEM DESIGN

Architecture

An upload initiates the workflow. SQS decouples object storage from compute, and SNS decouples compute from notifications.

Object storageAsynchronous messagingComputeNotificationsFailure handling
01Upload

Put a PDF, JPG, or PNG under uploads/.

02Enqueue

S3 sends an object-created event to SQS.

03Process

Lambda polls SQS and checks object metadata.

04Notify

SNS publishes the outcome to email.

05Recover

Repeated failures are delivered to the DLQ.

Standard SQS and S3 notifications can deliver duplicates. This demo is intentionally simple; a production service should make processing and notifications idempotent. Validation checks filename extension and size only—not the actual file contents.

04 / GET STARTED

Prerequisites & commands

Install Terraform and AWS CLI, then configure AWS credentials with permissions to create S3, SQS, SNS, Lambda, IAM, and CloudWatch resources. Commands below run from the project root.

λlambda/handler.py49 lines
import json
import logging
import os
from urllib.parse import unquote_plus

import boto3

log = logging.getLogger()
log.setLevel(logging.INFO)
s3 = boto3.client("s3")
sns = boto3.client("sns")
TOPIC_ARN = os.environ["TOPIC_ARN"]
MAX_BYTES = int(os.environ.get("MAX_BYTES", "5242880"))
ALLOWED_EXTENSIONS = (".pdf", ".jpg", ".png")


def lambda_handler(event, context):
    # Batch size is 1, so an unhandled exception retries this SQS message.
    for sqs_record in event["Records"]:
        envelope = json.loads(sqs_record["body"])
        for s3_record in envelope.get("Records", []):
            bucket = s3_record["s3"]["bucket"]["name"]
            key = unquote_plus(s3_record["s3"]["object"]["key"])

            # Ignore any unexpected event outside our upload prefix.
            if not key.startswith("uploads/"):
                continue

            # HEAD returns metadata without downloading the document.
            metadata = s3.head_object(Bucket=bucket, Key=key)
            size = metadata["ContentLength"]
            valid_type = key.lower().endswith(ALLOWED_EXTENSIONS)
            status = "SUCCESS" if valid_type and 0 < size <= MAX_BYTES else "REJECTED"

            message = (
                f"File: {key}\n"
                f"Bucket: {bucket}\n"
                f"Size: {size} bytes\n"
                f"Status: {status}\n"
                "Validation: extension is PDF/JPG/PNG and size is 1 byte to 5 MiB"
            )
            sns.publish(
                TopicArn=TOPIC_ARN,
                Subject=f"Document validation: {status}",
                Message=message,
            )
            log.info("Processed bucket=%s key=%s status=%s", bucket, key, status)

    return {"statusCode": 200, "message": "SQS batch completed"}

Test the workflow

Once the SNS subscription is confirmed, upload a sample PDF, image, or other local test file. The uploads/ path matters.

# Create any local file for the demo and upload it as a PDF name.
printf 'test document\n' > demo.pdf
aws s3 cp demo.pdf "s3://$(terraform output -raw bucket_name)/uploads/demo.pdf" \
  --region "$(terraform output -raw aws_region)"

# View Lambda logs (after the first invocation).
aws logs tail "/aws/lambda/$(terraform output -raw lambda_function_name)" \
  --follow --region "$(terraform output -raw aws_region)"
The small demo.pdf created above is a text file with a PDF extension. This project validates metadata only and will accept it as a demo input. It is not a valid PDF document.

06 / CLEANUP

Destroy the demo infrastructure

Empty the S3 bucket before destroying. This avoids errors because the bucket intentionally has force_destroy = false.

aws s3 rm "s3://$(terraform output -raw bucket_name)" --recursive \
  --region "$(terraform output -raw aws_region)"
terraform destroy
AWS charges can apply even to a small demo. Use a sandbox account, inspect the plan, and destroy resources when finished. Terraform state may contain sensitive data; do not commit it to version control. SQS-to-Lambda processing is at least once, so email notifications can be duplicated.
